# product-prd-coach

> 让 AI 按你产品的**真实现状**写 PRD，而不是凭空编一个看起来很完整的东西。

## 它解决什么

产品经理用 AI 做需求时，真正卡住的不是"不会写文档"，是这三件事：

| 痛点 | 表象 | 根因 |
|------|------|------|
| **AI 越界** | PRD 里混进你们产品根本没有的功能、不存在的文案、自己脑补的规则 | AI 不知道你的产品现状，只能在信息空白处自行发挥 |
| **原型交付不了** | AI 给的原型文件打不开、和团队用的工具不一样、同事看不了 | 交付物形态绑死在工具上 |
| **没有 PRD 规范** | 换了家公司就不知道 PRD 该写哪些章节 | 缺一套可裁剪的模块基线 |

## 核心机制

**1. 基准文件：先让 AI 看懂你的产品**
一份存放在项目里的 `baseline/`，记录产品现在长什么样——功能模块、交互规范、术语口径。AI 动笔前先读它，产出的新功能才能与现状衔接。

**2. 未描述区域的硬规则：宁可留白，不许编**
需求没说到的地方，AI 的默认行为是——**反问优先**（问你）→ **复用基准**（从你产品的既有规则继承并注明来源）→ **标记待确认**（留白）。

> 反面：AI 自行假设"失败时提示'操作失败，请重试'"。
> 正面：PRD 里写「待确认：失败态提示文案与是否需二次确认」。

这条规则是整个 skill 的第一优先级，高于任何写作规范。

**3. 不交付原型文件**
多模型实测 HTML 生成最快最稳。所以：生成单文件 HTML → 截图为图片/GIF → 嵌入 PRD 对应位置 → **只交付 PRD 文档**。

从源头绕开工具差异——不同人用墨刀、Figma、Axure 都一样能评审。

**4. 每轮交付都在喂养下一轮**
这次的 HTML 原型就是产品改版后的真实形态，下次迭代直接喂它，比喂官网还准。基准文件的维护成本随迭代递减。

## 快速开始

```bash
# 一键安装到本机所有已安装的 agent（推荐）
bash scripts/install.sh

# 或手动：把整个目录复制到任一平台的 skills 目录
cp -r product-prd-coach ~/.agents/skills/    # Grok / Gemini CLI / Copilot 通用
cp -r product-prd-coach ~/.claude/skills/    # Claude Code
cp -r product-prd-coach ~/.codex/skills/     # Codex（需开启 skills 开关，脚本会自动处理）
```

安装后在 agent 里说：

> "帮我写这个迭代需求的 PRD"

## 完整流程

```
阶段 B  基准文件   首次使用：引导你建立 baseline/（约 10 分钟，之后长期复用）
阶段 0  澄清背景   为什么做、给谁做、做成什么样算成功
阶段 1  用户场景   拆成可交付的用户故事，划定本期范围
阶段 2  方案设计   功能架构 + 流程图 + HTML 原型（覆盖五种状态）
阶段 3  PRD 撰写   按产品类型选模板，嵌入原型截图
阶段 4  自检交付   越界检查 → 反补基准 → 输出 Word
```

可以从任意阶段进入——已有明确需求就直接说，不必每次从零走。

### 首次使用需要提供什么

不抓取任何远程内容（隐私与内网都是硬约束）。你可以任选一种：

- **截图**：线上已有功能的页面截图，AI 识别现状生成基准初版
- **链接**：产品官网或网页版（需公开可访问）
- **文字模板**：使用 `assets/baseline-starter/` 下的模板填空

**三种都可以跳过**——跳过时全部未知项会落入「待确认」，并且 AI 会明确告诉你"这次会出现较多待确认项"，由你自己决定。

> 花这 10 分钟的意义：提供基准后 AI 的产出越界率显著下降，而且**以后每次迭代都不用再重新解释一遍产品**。

## 六类产品的 PRD 模板

写 PRD 前先确认产品类型，套用对应专属模块（其余章节共用）：

| 类型 | 专属必选章节 |
|------|--------------|
| C 端 | 用户分层与生命周期、增长/留存机制、埋点与转化漏斗 |
| B 端 | 角色权限矩阵、租户与数据隔离、审批流与工单衔接 |
| 数据产品 | 指标口径定义、数据来源与血缘、更新调度、可视化规则 |
| 策略产品 | 策略目标与约束、规则/模型逻辑、AB 实验与分流、兜底策略、效果评估 |
| 安全防御产品 | 风险场景分类、检出与拦截规则、误伤率与漏放率、告警处置链路、审计留痕 |
| 中台产品 | 能力抽象边界、接入方与调用契约、版本兼容与灰度、多业务复用策略 |

裁剪后保存到本地项目，下次直接引用。

## 跨平台

遵循 Agent Skills 开放标准（70+ 平台支持），**零外部依赖、不联网、不调 API**，禁网沙箱里也能跑。

已验证：Claude Code / Codex CLI / Grok / Gemini CLI / GitHub Copilot / Cursor / WorkBuddy。

在线文档发布（飞书/钉钉/企业微信）为**可选增强**，环境不支持时自动降级为本地交付，不影响任何产出完整性。

## 常见问题

**Q：不提供基准文件会怎样？**
能用，但 PRD 里会有较多「待确认」标记。AI 不会拿你的产品假装了解——这是刻意设计，宁可留白也不编。

**Q：反问会不会很烦？**
每轮不超过 3 个问题，且问的是真正阻塞的点（如"失败后怎么提示"），不是走流程。答不上来的可以回答"按你们常规做"，AI 会转为「待确认」。

**Q：为什么不直接给原型文件？**
因为团队工具不统一。截图嵌入 PRD 后，用墨刀的、用 Figma 的、根本不装工具的评审人，看到的是同一份东西。

**Q：支持英文项目吗？**
支持。PRD 输出语言跟随你的输入。

**Q：我的基准文件会被上传吗？**
不会。skill 全程只读写本地项目文件，不联网、不调用任何外部接口。
